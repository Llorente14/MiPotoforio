# MiPotoforio

Personal portfolio of **Axel Chrisdy Sanjaya**, Informatics Engineering student at Universitas Tarumanagara (UNTAR).

The landing page tells its story as the sky turns from night to day. Kaito Kid throws a card in the Hero, and the card opens into the rest of the page. Below that are cel-shaded 3D scenes, drifting sakura petals, curated projects and certificates, and a live GitHub contribution heatmap.

**Live site:** [mipotoforio.vercel.app](https://mipotoforio.vercel.app)

## Features

- **Hero with Card Transition.** A scroll-driven animation in which Kaito Kid throws a card that fills the screen and opens into the About section.
- **Sky Theme.** Light and Night skies, switchable from the navbar and remembered between visits.
- **Cel-shaded 3D scenes** with ink outlines for UNTAR Building 2, a Kiyomizu-dera style pagoda and Kaito Kid; the fun fact runs a looping Akai Shuichi clip cut to the striped-sun disc.
- **Projects and Certificates**, each with a landing preview and a full list page, plus a CV download. Project pages have an auto-advancing screenshot gallery and a videos & links section.
- **GitHub Activity.** A contribution heatmap fetched at build time and refreshed daily.
- **Command palette** opened with <kbd>Ctrl</kbd>+<kbd>K</kbd> / <kbd>⌘</kbd>+<kbd>K</kbd>, for fuzzy search across sections, projects, certificates and links.
- **Device-aware.** Phones and tablets never start WebGL and get still renders instead. `prefers-reduced-motion` is respected throughout.

## Getting started

Requirements: Node.js ≥ 22.22 and [pnpm](https://pnpm.io).

```sh
pnpm install                       # also enables the repo's git hooks
pnpm exec playwright install chromium
pnpm dev                           # http://localhost:4321
```

### Scripts

| Command | Description |

| `pnpm check` | Type-check Astro and TypeScript files |
| `pnpm test` | Run unit tests (Vitest) |
| `pnpm test:e2e` | Build, serve and run E2E tests on desktop and mobile profiles |

## Editing content

All content (profile, projects, certificates, current learning, currently watching) lives in typed Astro Content Collections under `src/content/`. Schemas are validated at build time. Adding a project means adding one MDX file; no component changes are needed.

## 3D assets

Every model is generated by a Blender Python script. The script is the source of truth, so edit it, re-run it, and commit both the script and its outputs.

```sh
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" -b --factory-startup -P blender/<model>.py
```

| Script | Model | GLB nodes | Used in |
|---|---|---|---|
| `kaito.py` | Kaito Kid, head to mid-thigh, the ace-of-clubs calling card between two gloved fingers | `Kaito`, `Card` (animated) | Hero, Card Transition |
| `untar.py` | UNTAR Building 2 | `Untar` | About section |
| `temple.py` | Three-storey pagoda, Kiyomizu-dera style | `Temple` | Current Learning |

`blender/toon.py` contains the shared helpers: smooth primitives, lofts and tapered strands, join, export, and the render-only toon shader with an inverted-hull ink outline. The anime faces come from vector sources (`blender/decals/*.svg`, projected onto the head with `decal()`): run `node scripts/textures.mjs` before the Blender scripts; it writes to the gitignored `blender/.cache/`. Kaito's 3D card uses `blender/textures/card-front.png` and `card-back.png` (the ace of clubs and its harlequin back); the page card is the vector `src/assets/card/front.svg`.

Each script writes:

- `public/models/<id>.glb`: plain PBR materials (the site applies its own toon shading and outline), Draco-compressed, Y-up, transforms baked (origin at 0,0,0). Kaito is about 180 KB, UNTAR and the pagoda about 45 KB.
- `public/renders/<id>.webp`: a transparent cel-shaded still render with ink outlines.

You can also edit a model by hand in Blender. Export it with the same file name and node names, and keep Draco compression on. Re-running the script overwrites manual edits.

### Adding a model to the site

1. Drop `<id>.glb` into `public/models/` and `<id>.webp` into `public/renders/`.
2. Place `<ModelSlot client:visible id="<id>" aspect="4 / 3" alt="..." />` where it should appear (`src/components/ModelSlot.tsx`). Add the id, its camera and framing to `ModelId` and `framing` in `src/components/ModelScene.tsx` if it is new.

On desktop the slot loads the GLB (Draco decoder is self-hosted in `public/draco/`) in a lazy React Three Fiber scene with no frame around it. The scene swaps the glTF materials for three-tone toon materials, adds an inverted-hull ink outline, and renders on demand (only when the pointer moves or the page scrolls). On phones and tablets (`max-width: 767px` or a coarse pointer), or without WebGL, it shows the still render and never starts WebGL. A missing GLB leaves the slot empty, and a missing WebP falls back to `public/renders/placeholder.svg`.

## Deployment

The site deploys to Vercel. Every push to `main` triggers a deploy, and a daily rebuild keeps the GitHub heatmap fresh.

| Variable | Where | Purpose |
|---|---|---|
| `GITHUB_TOKEN` | Vercel env, local `.env` | Fine-grained read-only token for the contribution heatmap (GraphQL API). Optional: without it the build reads the public contributions page instead, and the section only shows its empty state if GitHub cannot be reached. |

Test builds set `GITHUB_CONTRIBUTIONS=off` so they never touch the network.

Never commit `.env` files or tokens.

### Deploy & secrets

1. Import this repo in Vercel (New Project). The Astro preset works as is.
2. In GitHub, create a fine-grained personal access token with read-only access (public repositories only is enough). Add it in Vercel under Settings > Environment Variables as `GITHUB_TOKEN`. For local development, copy `.env.example` to `.env` and fill it in.
3. In Vercel, open Settings > Git > Deploy Hooks and create a hook for the `main` branch. Copy its URL.
4. In GitHub, open the repo Settings > Secrets and variables > Actions and save the URL as the repository secret `VERCEL_DEPLOY_HOOK_URL`.

The workflow `.github/workflows/daily-deploy.yml` then calls the hook once a day (03:00 UTC) and can also be run by hand from the Actions tab. Without the secret it only logs a skip message.
